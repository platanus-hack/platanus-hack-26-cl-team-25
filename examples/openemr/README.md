# OpenEMR 8.2.0 example

## Purpose

The onboarding of an unmodified third-party PHP application, OpenEMR `v8_2_0` (commit `6125a2fd8089`), to
Immune's generic runtime (`app.runtime: generic`, `database.kind: mysql`). No file of OpenEMR is changed and
no vulnerability is planted: `fetch.py` refuses a tree that differs from the tag. The directory holds only
the onboarding files; the application's source is cloned by `fetch.py`. The guide, in Spanish, is
[`docs/openemr.md`](../../docs/openemr.md).

## How it runs

Prerequisites: Docker, `git`, network access to GitHub and Docker Hub, the repository's `.venv`. From the
repository root:

```bash
python examples/openemr/fetch.py                  # clone and verify the tag, add the onboarding, tag openemr-t0
bin/immune up --project examples/openemr/app      # gateway 127.0.0.1:8280, dashboard 127.0.0.1:8290
python examples/openemr/legit.py                  # legitimate traffic of the synthetic clinic's staff
python examples/openemr/attacks.py                # attack requests against OpenEMR surfaces, through the gateway
```

`fetch.py [--dest DIR] [--repo LOCAL_CLONE]` creates the project directory (default `app/` under this
directory, not in the repository): it clones the tag, checks the commit and `version.php`, copies `overlay/`
into it, verifies that `git diff v8_2_0` of the tracked tree is empty, commits and tags `openemr-t0`.

Ports (`overlay/.immune/config.yaml`, all on 127.0.0.1): gateway 8280, gateway admin 8281, dashboard 8290,
fleet 8270.

## Layout

| Path | Role |
|---|---|
| `fetch.py` | Pinned clone, version check, onboarding overlay, tag `openemr-t0` |
| `overlay/Dockerfile.immune` | The official image pinned by digest, plus what the fleet's sandbox needs (read-only root, non-root, writable `/tmp`), with the release's sources copied over the docroot |
| `overlay/immune-runtime/` | Apache config, PHP ini, `sqlconf.php` from the environment, `start.sh`, `seed.sh` and `seed-clinic.php` (OpenEMR's installer plus the synthetic clinic), `whoami.php` (session introspection for the gateway), `tests.sh` |
| `overlay/.immune/config.yaml` | Project config: generic runtime, MySQL, introspection auth, `shadow.tracer` (Xdebug call traces), `legit.normalize`, `autopatch: merge` |
| `overlay/.immune/openapi.yaml` | Generated by `gen_openapi.py` from the tag (REST/FHIR spec and the UI scripts) |
| `overlay/.immune/shadow/columns.yaml` | Shadow-data classification of the installed schema, generated by `gen_columns.py` and reviewed by hand |
| `overlay/.immune/openemr_identity.py` | Sidecar profile: `ensure_user`, `identity_headers` (logs in on the clone), `rewrite_request` (CSRF tokens), `public_paths`, `extra_oracles` |
| `legit.py`, `attacks.py` | Demo traffic (`--base`, default `http://127.0.0.1:8280`) |
| `seed-rules.sh` | Posts one optional policy rule to the gateway admin API |
| `AGENT_BRIEF.md` | Red-team brief (Spanish) an operator hands to a coding agent to exercise the five CVEs of OpenEMR 8.2.0 against the local lab, through the gateway only. Its credentials belong to the synthetic clinic the seed creates |

## Configuration

Everything is in `overlay/.immune/config.yaml`; the keys are defined in
[`contracts/product.md`](../../contracts/product.md). Specific to this example:

| Key | Value | Effect |
|---|---|---|
| `data.prod_url_env` | `OPENEMR_DATABASE_URL` | When set, production uses that MySQL database; otherwise a MariaDB container is installed and seeded by `seed.sh` |
| `auth.kind` | `introspect`, path `/_immune/whoami` | The gateway asks production who owns the session cookie |
| `auth.login.user_env`, `password_env` | `OPENEMR_VERIFY_USER`, `OPENEMR_VERIFY_PASSWORD` | Account for the post-deploy verification; defaults to a seeded synthetic account |
| `shadow.tracer` | `php-xdebug`, `/tmp/immune-trace` | Clones run the `-trace` image, so evidence carries a PHP file and line ([`sidecar/README.md`](../../sidecar/README.md)) |
| `tests.command` | `sh /immune/tests.sh` | The `tests` gate: `php -l` on every changed file and a bootstrap of OpenEMR; the image has no PHPUnit |
| `audit.enabled` | `false` | No class audit |

## Behaviour

Requests follow the same path as for any generic-runtime project: gateway, detonation in a clone made of the
app container, a MariaDB and the sidecar (`python -m sidecar`, MySQL proxy), incident, rule, patch through the
five gates, blue/green deploy. In addition to the sidecar's oracles, `extra_oracles` in
`openemr_identity.py` emits application-specific events: `acl` (a billing read by a user whose ACL groups do
not allow it, checked against the clone's ACL tables), `mfa` (a token issued without the second factor) and
`xss` (active markup stored or echoed).

`attacks.py` prints, per request, whether the gateway blocked it, a clone answered it, or it was forwarded.

## Tests

No automated test in the repository runs this example: it needs the OpenEMR clone and its image. The
components it relies on are unit-tested elsewhere (`sidecar/tests/test_mysqlproxy.py`,
`sidecar/tests/test_phptrace.py`, `immune/tests/test_mysql_runtime.py`). No recorded result of a detection on
this example is in the repository.

No defect is planted: the app is OpenEMR v8_2_0 as released (`fetch.py` checks the commit and that the tree
equals the tag). The surfaces the gateway and the clones watch most closely, and the oracle expected on each:

| Surface | Route | Oracle |
|---|---|---|
| Patient search / finder | `interface/main/finder/*.php`, `patient_select.php` | `sql` |
| Documents | `controller.php?document&retrieve` | `file` |
| REST / FHIR API | `/apis/default/api/*`, `/apis/default/fhir/*` | `sql`, `owner` |
| Administration | `interface/super/edit_globals.php`, `usergroup_admin.php`, `main/backup.php` | `proc`, `file` |
| Login | `interface/main/main_screen.php?auth=login` | none (the password is `x-sensitive`) |

## Limits

- The `tests` gate is a syntax and bootstrap check, not OpenEMR's test suite.
- `acl`, `mfa` and `xss` are written for OpenEMR's tables and routes; they are part of this profile, not of
  the sidecar.
- A clone holds synthetic credentials, so a request authenticated with a production bearer token gets 401 in
  the clone (verdict `inconclusive`).
- `seed-rules.sh` posts to `/rules` on the admin port; the gateway's admin routes are under `/_admin/`
  (`admin_app` in `gateway/core.py`), so the script as written does not create the rule.

The project-wide list is in [`docs/limites.md`](../../docs/limites.md).
